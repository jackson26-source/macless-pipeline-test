# macless-pipeline-test

A throwaway Capacitor app whose only job is to exercise the Macless Android
pipeline end to end: build → sign → upload to Google Play.

**This is not a product.** Don't build anything on it, and don't reuse the
package name — `dev.macless.pipelinetest01` is permanently claimed by the
matching Play Console listing and can never be used for anything else.

## What's here

- `capacitor.config.json` — `appId` is what becomes the Android
  `applicationId`, and it must match the Play Console listing exactly or the
  upload is rejected.
- `www/` — a single static page. Capacitor needs a `webDir` to copy; the
  contents are irrelevant to what's being tested.
- `.github/workflows/android-build.yml` — the pipeline under test. The
  `android/` directory is generated by `npx cap add android` on every run and
  is deliberately not committed.

## Running it

Set these repository **secrets**:

| Secret | Note |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `openssl base64 -in release.keystore -A` |
| `ANDROID_KEYSTORE_PASSWORD` | |
| `ANDROID_KEY_ALIAS` | |
| `ANDROID_KEY_PASSWORD` | **must equal the keystore password** |

The two passwords being identical is not a style preference. `keytool`
creates PKCS12 keystores by default, and PKCS12 has no separate key password
— it prints a warning and ignores the one you typed. The workflow now checks
this and fails with an explanation rather than letting `jarsigner` report
`key associated with <alias> not a private key`.

And this repository **variable**:

| Variable | Value |
|---|---|
| `ANDROID_PACKAGE_NAME` | `dev.macless.pipelinetest01` |

Then: Actions → *Build and upload to Google Play* → **Run workflow**, with
**skip_upload** ticked for the first run. Download the `signed-aab` artifact
and upload it by hand in Play Console under Testing → Internal testing.
Google Play will not accept API releases for an app that has never had a
build uploaded through the Console.

Once that first manual release exists, run the workflow again without
`skip_upload`.
